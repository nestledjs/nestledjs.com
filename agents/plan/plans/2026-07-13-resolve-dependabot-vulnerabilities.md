# Plan: Resolve open Dependabot vulnerabilities (PIR-134)

**Linear issue:** [PIR-134](https://linear.app/pirate-and-fox/issue/PIR-134)
**Repo:** nestledjs.com · **Base branch:** `develop`
**Branch to create:** `fix/pir-134-dependabot-vulns`
**Mode:** Fresh work (not a revision).

## Objective

Drive the GitHub Dependabot open-alert count to **0** for `nestledjs/nestledjs.com` by
upgrading `next` within its current major, adding two `pnpm` overrides, and refreshing
the lockfile — with `pnpm build` succeeding and the site rendering normally.

## Context: the actual alerts

As of planning there are **16 open alerts** (the issue said 15; one moderate `js-yaml`
alert was added after filing). They collapse into just **four packages**:

| Package | Sev(s) | Locked version | Fix version | How it's pulled |
|---|---|---|---|---|
| `next` | 7 high, 4 med, 2 low (13 alerts) | `15.5.12` | ≥ **15.5.18** | direct dep (`^15.0.0`) |
| `shell-quote` | 1 **critical** (GHSA-w7jw-789q-3m8p) | `1.8.3` | `1.8.4` | transitive via `concurrently@9.2.1` (devDep) |
| `postcss` | 1 med (GHSA-qx2v-qp2m-jg93) | `8.4.31` (bundled by `next`) + `8.5.6` (via `@tailwindcss/postcss`) | `8.5.10` | transitive |
| `js-yaml` | 1 med (GHSA-h67p-54hq-rp68) | `4.1.1` | `4.2.0` | direct dep (`^4.1.1`) |

Key facts that make this low-risk:
- **No major-version jump is needed.** Every `next` alert is patched at `15.5.16`, and the
  one incomplete-fix follow-up (`#2`, GHSA-26hh-7cqf-hhc6) at `15.5.18`. The latest 15.x
  release is **`15.5.20`** (npm dist-tag `backport`; `latest` is `16.2.10`, which we
  deliberately avoid per the acceptance criteria). `15.5.20 ≥ 15.5.18` → clears all 13.
- `next`'s declared range `^15.0.0` **already permits** `15.5.20`; this is a lockfile bump.
  We also raise the floor to `^15.5.20` so the vulnerability cannot silently reappear.
- `@markdoc/next.js@0.3.7` declares `next: "*"` as its peer — no upper bound, so the bump
  is safe for the Markdoc integration.
- `js-yaml`'s `4.2.0` already satisfies the declared `^4.1.1`; lockfile bump + raise floor.
- `shell-quote` and `postcss` are transitive, so they are fixed with `pnpm.overrides`
  (the repo already uses this pattern for `tar`/`glob`/`lodash`/`minimatch`).

## Files to change

- `package.json` — bump two direct deps' declared ranges + add two overrides.
- `pnpm-lock.yaml` — regenerated by `pnpm install`.

## Implementation steps

### 1. Branch
```shell
cd "$(git rev-parse --show-toplevel)"
git checkout develop && git pull
git checkout -b fix/pir-134-dependabot-vulns
```

### 2. Edit `package.json`

**a.** Raise the two direct-dependency floors:
- `"next": "^15.0.0"` → `"next": "^15.5.20"`
- `"js-yaml": "^4.1.1"` → `"js-yaml": "^4.2.0"`
- (devDependencies) `"eslint-config-next": "^15.0.0"` → `"^15.5.20"` so it tracks `next` in lockstep.

**b.** Add two entries to the existing `pnpm.overrides` block (keep the current four):
```json
"overrides": {
  "tar": ">=7.5.8",
  "glob": ">=10.5.0",
  "lodash": ">=4.17.23",
  "minimatch": ">=10.2.1",
  "shell-quote": ">=1.8.4",
  "postcss": ">=8.5.10"
}
```

> **Note on the `postcss` override:** `next` internally pins `postcss@8.4.31` as a direct
> dependency (not a caret range), so bumping `next` alone will NOT lift it — the override is
> required to force `postcss ≥ 8.5.10` across the whole tree (next's bundled copy **and**
> `@tailwindcss/postcss`'s `8.5.6`). postcss is backward-compatible within 8.x; the build
> check in step 4 is the guard.

### 3. Reinstall
```shell
pnpm install
```
This resolves `next@15.5.20`, applies the overrides, and rewrites `pnpm-lock.yaml`.

Verify the lockfile no longer contains vulnerable versions:
```shell
grep -E "shell-quote@1\.8\.[0-3]:|postcss@8\.(4\.|5\.[0-9]:)|next@15\.5\.1[0-7]:|js-yaml@4\.1\." pnpm-lock.yaml
```
Expected: **no matches** (all bumped). Confirm the new resolutions are present:
```shell
grep -E "next@15\.5\.20:|shell-quote@1\.8\.[4-9]|postcss@8\.5\.1[0-9]|js-yaml@4\.2" pnpm-lock.yaml
```

### 4. Build & verify locally
```shell
pnpm build          # validates all routes; must succeed
pnpm type-check     # tsc --noEmit
pnpm lint           # next lint
pnpm audit --audit-level=high   # matches ci:security; expect no high/critical
```
Spot-check key pages render in `pnpm dev` (localhost:3001): the docs home `/`, one
`/docs/<slug>` page, and confirm the Markdoc code-fence rendering (`Fence`) and search still
work — these exercise the `@markdoc/next.js` + `next` + `postcss`/`tailwindcss` paths that
the bumps touch.

### 5. Confirm alert closure
After the PR merges and Dependabot re-scans, the open-alert count should reach **0**. If any
alert cannot be auto-resolved (e.g. no non-major fix), dismiss it in the GitHub Security tab
with a stated reason and note that reason in the PR — do **not** leave it silently open.

## PR requirements (per acceptance criteria)

- Title: `fix(deps): resolve open Dependabot vulnerabilities (PIR-134)`.
- Body must state: `next 15.5.12 → 15.5.20` (patch/minor within major 15 — **no major jump**),
  `shell-quote` and `postcss` pinned via `pnpm.overrides`, `js-yaml → 4.2.0`.
- Explicitly note **no framework major-version jump was taken** (stayed on Next 15; Next 16
  deliberately avoided) and that no breaking-change handling was required.
- List the 16 alerts → 0 outcome (or any dismissed alert + reason).

## Acceptance criteria (from the issue)

- [ ] Dependabot open-alert count is 0 (or unfixable alerts dismissed with a stated reason).
- [ ] `pnpm build` succeeds and the site renders normally (key pages spot-checked in preview).
- [ ] No major-version framework jumps without noting breaking-change handling in the PR.

## Risks & mitigations

- **`postcss` override reaches into next's bundled copy.** Low risk (postcss is stable across
  8.x); mitigated by `pnpm build` + page spot-check in step 4. If the build breaks, scope the
  override narrowly or investigate next's expected postcss version — but this is not expected.
- **A new alert appears between planning and execution.** Re-run the alert fetch
  (`gh api -X GET /repos/nestledjs/nestledjs.com/dependabot/alerts -f state=open --paginate --slurp`)
  at execution start; if a new package appears, apply the same lockfile-bump-or-override
  approach and note it.
- **Next 16 pressure.** Out of scope — the acceptance criteria bar unexplained major jumps,
  and 15.5.20 clears every current alert. Leave Next 16 to a separate deliberate upgrade.

## Out of scope

- Upgrading to Next 16.
- Unrelated `pnpm outdated` bumps not tied to a security alert.
- Adding/altering `.github/dependabot.yml` (none currently exists; not required by the issue).
